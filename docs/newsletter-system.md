# Newsletter System

A domain-based email newsletter that generates and sends daily digests using content from Notion, processed by Claude AI, and delivered via Gmail.

## Architecture

```
Subscriber signs up
  → email + domain preferences saved to Supabase
  → verification email sent via Gmail

Subscriber clicks verify link
  → marked as verified in Supabase
  → gains access to Knowledge Base

GitHub Actions cron (7 AM UTC daily)
  → POST /api/newsletter/send  (one call per domain)
      → fetch Notion root page content
      → Claude generates HTML newsletter (subject + body)
      → send to all verified subscribers for that domain via Gmail
      → log result to newsletter_logs table
```

## Domains

| Value | Label | Notion env var |
|---|---|---|
| `platform` | Platform Engineering | `NOTION_PLATFORM_ROOT_PAGE_ID` |
| `cpp` | C++ Development | `NOTION_CPP_ROOT_PAGE_ID` |
| `os` | OS Development | `NOTION_OS_ROOT_PAGE_ID` |
| `5g` | 5G & Networking | `NOTION_5G_ROOT_PAGE_ID` |
| `finance` | Finance & Stocks | `NOTION_FINANCE_ROOT_PAGE_ID` |

## Send schedule

Configured in `.github/workflows/newsletter-cron.yml`:

```
0 7 * * *   →   7:00 AM UTC = 12:30 PM IST
```

To change the time, edit the cron expression in that file.

## Email content

Content is generated by Claude (`claude-haiku-4-5`) using this structure:

- Subject line (auto-generated)
- Brief greeting
- 3–5 key insights from the Notion page, each with a bold heading
- Closing thought / call to action
- Unsubscribe link at the bottom

The source material is the **plain text** of the Notion root page for that domain (not child pages — just the root). To control what goes into the newsletter, edit the root page content in Notion.

## API routes

| Route | Method | Auth | Purpose |
|---|---|---|---|
| `/api/newsletter/subscribe` | POST | none | Subscribe with email + domains |
| `/api/newsletter/verify` | GET | token (query param) | Verify email address |
| `/api/newsletter/unsubscribe` | POST | none | Unsubscribe from domains |
| `/api/newsletter/send` | POST | `CRON_SECRET` | Generate and send newsletter |

## Required environment variables

```env
# Supabase
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=

# Gmail OAuth2
GMAIL_CLIENT_ID=
GMAIL_CLIENT_SECRET=
GMAIL_REFRESH_TOKEN=
GMAIL_SENDER_EMAIL=

# Notion (one per domain)
NOTION_API_KEY=
NOTION_PLATFORM_ROOT_PAGE_ID=
NOTION_CPP_ROOT_PAGE_ID=
NOTION_OS_ROOT_PAGE_ID=
NOTION_5G_ROOT_PAGE_ID=
NOTION_FINANCE_ROOT_PAGE_ID=

# Anthropic Claude
ANTHROPIC_API_KEY=

# Cron auth
CRON_SECRET=

# Site URL
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

## Manual testing

Use the test script for local testing without GitHub Actions:

```bash
# Send newsletter for a specific domain
node scripts/test-triggers.js newsletter platform

# Send for all domains
node scripts/test-triggers.js newsletter
```

See [docs/testing-triggers.md](testing-triggers.md) for full details.

## GitHub Actions secrets

For the cron workflows to work in production, add these secrets to your GitHub repo (**Settings → Secrets and variables → Actions**):

| Secret | Value |
|---|---|
| `SITE_URL` | Your deployed site URL (e.g. `https://yoursite.com`) |
| `CRON_SECRET` | Same value as your `CRON_SECRET` in `.env.local` |
